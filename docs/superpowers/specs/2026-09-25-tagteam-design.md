# TagTeam — Design Spec

Status: **approved** — architecture, UI, data model (§4) + engine (§5) approved 2026-09-25.

## 1. Product summary

Mobile-first, offline-first PWA for small groups (families, flatmates, teams) to track personal
recurring tasks ("brush teeth", daily) and see each other's progress so they can nudge each other.

- Users belong to one or more **groups**. One group is **active** at a time and stays active until
  the user switches manually (like Slack workspaces).
- Users create and complete **their own tasks only**. Everyone in the group can **see** all members'
  tasks and **nudge** them.
- Tasks are one-off or **recurring**: daily, weekly, monthly, every N days/weeks/months (weekly may
  pick weekdays).
- A task is due on a date with an **optional time** (default: end of day / period), in the owner's
  timezone.
- **Full history** of every occurrence: done on time, done late (by how much), missed.
- Works fully offline; all changes sync when back online.
- Push notifications: due/overdue reminders to the owner, and nudges from group members.

## 2. Decisions log

| Topic | Decision |
|---|---|
| Hosting | Self-hosted, single Docker image, behind Cloudflare Zero Trust (Access) via `cloudflared` |
| Distribution | Image built by GitHub Actions and published to GitHub Container Registry (`ghcr.io`); README has a copy-paste `docker-compose.yml` |
| Auth | Own accounts in-app (Access is only an outer gate). Better Auth: passkeys primary, email+password fallback |
| Joining groups | 6-digit numeric code, **single use**, generated by any member, shared manually; unused codes expire after 7 days; redeem attempts rate limited per user |
| Abuse protection | No IP-based limits (cloudflared hides client IPs). Invite redeem limited per user (5/min, 20/h). Sign-in brute force is stopped by Cloudflare Access; auth POSTs from an untrusted Origin are rejected |
| Ownership | Own tasks only; others view + nudge |
| Notifications | Web push: due/overdue reminders + nudge button |
| Due time | Date + optional time, owner's IANA timezone |
| Missed recurrences | One open instance per task; gaps logged as missed (see §5) |
| Stack | React + Vite SPA, Serwist SW, Dexie (IndexedDB); Hono on Node, Better Auth, Drizzle + SQLite, SSE, web-push |
| Sync | Outbox of idempotent mutations → POST /api/sync/push; GET /api/sync/pull?cursor= returns rows with seq > cursor (+ full snapshot of newly joined groups, + removedGroupIds); live pokes over SSE (GET /api/live) |

## 3. Architecture

```
Phone (installed PWA)                        Server (1 Docker image, behind cloudflared)
┌───────────────────────────────┐            ┌──────────────────────────────────┐
│ React UI                      │            │ Hono                             │
│   ↕ live queries (Dexie)      │            │  /api/auth/*   Better Auth       │
│ IndexedDB: tasks, events,     │  push ───► │  /api/sync/push  apply muts,     │
│   members, groups, outbox     │ ◄── pull   │                  idempotent      │
│ Sync worker (outbox, cursor)  │ ◄── SSE ── │  /api/sync/pull  rows > cursor   │
│ Serwist SW: precache shell,   │   "poke"   │  /api/live       SSE pokes       │
│   push notifications          │            │  scheduler: due/overdue push     │
└───────────────────────────────┘            │ SQLite (Drizzle), web-push VAPID │
                                             └──────────────────────────────────┘
```

Monorepo packages:

- `packages/core` — pure TypeScript shared by client + server: recurrence rules, occurrence engine,
  history derivation, mutation types + validation. No I/O. Heavily unit-tested.
- `apps/web` — React SPA, Dexie store, sync worker, Serwist service worker.
- `apps/server` — Hono API, Better Auth, Drizzle/SQLite, sync endpoints, SSE live stream, push scheduler.

### 3.1 Local-first data flow

- UI reads/writes **only IndexedDB** (Dexie live queries). Never blocks on network.
- Each write = local row change + mutation appended to `outbox` with client UUID.
- Sync triggers: app open, `online` event, SSE poke, after local writes (debounced ~500 ms),
  periodic while visible.
- **Push:** send outbox batch → server applies each mutation idempotently (mutation id dedupe table),
  validates ownership/membership, returns results. Rejected mutations are dropped locally and the
  affected rows re-pulled.
- **Pull:** `GET /api/sync/pull?cursor=N` returns all rows visible to user with `seq > N`
  (tombstones included), plus new cursor.
- **Live:** SSE stream per signed-in client (GET /api/live); server sends "poke" after commits touching the user's groups; client pulls. Keep-alive comment every 25 s.

### 3.2 Conflict handling

- Completions, un-completions, nudges: **append-only events** keyed by client UUID → never conflict.
- Task field groups (title, notes, schedule, archive) are last-writer-wins by the mutation's client
  timestamp, clamped to server time + 5 min; ties go to the later arrival.
- Duplicate completion of the same occurrence (two offline devices): second is ignored during
  derivation (kept in log).

### 3.3 Cloudflare Access expiry

If a sync response is not our JSON (redirect/HTML from Access), sync pauses, UI shows a
"Session expired — tap to reconnect" banner (opens top-level navigation to re-auth). Outbox is
retained; nothing is lost.

### 3.4 Time

All instants stored UTC. Each task stores its owner's IANA timezone so "08:00 daily" stays correct
across DST. Occurrence keys are local dates (`2026-09-21`) in that timezone.

### 3.5 Push scheduler

Server job every minute computes due / overdue tasks with the same `core` engine and sends web
push. Dedupe via `(taskId, occurrenceKey, kind)` unique log. Nudges send immediately (rate
limited: 1 nudge per sender per task per 30 min).

### 3.6 Sync protocol

- Mutations (`@tagteam/core` `Mutation`): `task.create`, `task.update`, `task.schedule`, `task.archive`,
  `task.complete`, `task.uncomplete`, `task.nudge`. Each has a client UUID `id` and client `at`.
- `POST /api/sync/push { mutations }` (≤ 100) → per-mutation `applied | duplicate | rejected (reason)`.
  Rejected mutations are dropped by the client and its data re-pulled.
- `GET /api/sync/pull?cursor=N` → `{ cursor, groups, members, tasks, events, removedGroupIds }`.
- Nudges: any other active member, once per sender per task per 30 min.

## 4. Data model

Better Auth owns `user`, `session`, `account`, `passkey`. App tables (all synced tables carry
`seq` (global monotonic) and `deletedAt` tombstone):

- `profile` — userId, displayName, avatarColor, timezone, activeGroupId
- `group` — id, name, createdBy, createdAt
- `membership` — groupId, userId, role (`admin` | `member`), joinedAt, leftAt
- `invite_code` — code (6 digits, unique among active), groupId, createdBy, expiresAt (7 days),
  usedBy, usedAt, revokedAt. Single use: consumed atomically on join. Redeem attempts rate limited
  per user (5/min, 20/h).
- `task` — id, groupId, ownerId, title, notes, timezone, startDate, rules (JSON RuleVersion[] —
  each {effectiveFrom, rule, dueTime}), archivedAt, createdAt, clocks (LWW per field group), seq
- `task_event` — id (= mutation id), taskId, groupId, userId, type, occurrenceKey, refEventId, at
  (client, clamped), receivedAt, seq
- `push_subscription` — userId, endpoint, keys, deviceLabel
- `notification_log` — taskId, occurrenceKey, kind; unique
- `applied_mutation` — mutationId, userId, appliedAt (idempotency)
- `sync_state` — key, value (global change sequence)

`group`, `profile`, and `membership` also carry `seq`.

Recurrence rule shape:

```ts
type Rule =
  | { freq: 'day';   interval: number }
  | { freq: 'week';  interval: number; weekdays: Weekday[] }   // default: startDate's weekday
  | { freq: 'month'; interval: number; monthDay: number | 'last' } // 31 clamps to last day
```

## 5. Occurrence & history engine

Chosen behaviour: **one open instance, gaps logged.**

Example — "Brush teeth", daily 08:00; not done Mon or Tue, done Wed 10:00:

```
Mon  ○ missed
Tue  ○ missed     (Mon still open)
Wed  ● done late  (10:00, +2h)
Thu  ◐ upcoming
```

History is **derived, never generated** — a pure function of rules + events + now. No cron needed
for history; identical result offline and online.

- **Slot:** each scheduled occurrence has a key (local date), a period start, and a due instant
  (dueTime or end of period).
- **Open instance:** the earliest slot (≥ startDate) not yet closed.
- **Completion at t:** closes the occurrence scheduled for that local date, when one exists.
  Earlier open occurrences become missed. If no occurrence is scheduled that day, completion closes
  the earliest open slot. A completion is *on time* if t ≤ due, else *late* by (t − due).
- **Next open after completion:** latest slot whose period has started by t, if it is after the
  closed slot; otherwise the next slot after the closed one.
- **Missed:** earlier uncompleted slots become missed when a later slot is completed. Slots that
  become due while the current slot stays open also become missed, shown as "missed (X still open)".
- **Overdue card:** while open slot's due < now, card shows "Overdue since <day> · N missed".
- **Uncompleted:** cancels a referenced completion; derivation re-runs.
- **One-off tasks:** single slot; stays open (overdue) until done.

## 6. UI (approved 2026-09-25)

Mobile-first, thumb-first. Bottom nav: **Today · Team · (+) · History · Me**. Center (+) opens
the add-task sheet. All tap targets ≥ 44 px. Respect safe-area insets; light + dark themes.

### 6.1 Header (all tabs)

- Active group name + chevron → bottom sheet: your groups, "Create group", "Join with code".
  Selection persists until changed manually.
- Sync chip: hidden when online + synced; amber "Offline · N queued" when offline or pending.
- Access-expired banner: "Session expired — tap to reconnect".

### 6.2 Today (home)

- Day title + "X of Y done today" + thin progress bar.
- Sections: **Overdue** (red text: "Since Mon 08:00 · 2 missed"), **Today** (by due time, then
  untimed; completed items sink to bottom, struck through with "Done 07:42").
- **Upcoming hidden by default** behind a "Show upcoming" toggle at list end (state remembered
  per device).
- Tap circle = complete (haptic + check animation + 5 s "Undo" toast). Swipe right = complete.
  Tap row = task detail/history. Recurring tasks show a small repeat icon.
- Empty state: "Add your first task" + (+) hint.

### 6.3 Team

- Member rows: avatar, name, "N of M today" progress bar, red "N overdue" pill.
- Tap member → expands inline to their tasks. Overdue tasks show **Nudge** button; after nudging
  shows "Nudged 5m ago" (rate limit 1 / sender / task / 30 min).
- Invite (user-plus icon) → "Generate code" → single-use 6-digit code with copy/share; list of
  your pending codes (expires in N days) with revoke.

### 6.4 Add / edit task (bottom sheet)

- Opens with keyboard focused on title. Enter submits.
- Repeat chips: **Once · Daily · Weekly · Monthly · Custom** (default Once).
- Custom reveals: "Every [N] [days|weeks|months]"; weeks → weekday toggles (M T W T F S S);
  months → day-of-month or "last day".
- Chips: "Starts today" (date picker), optional "By HH:MM" time.
- Single primary button "Add task" / "Save".
- Edit same sheet, from task detail; plus Archive (history kept).

### 6.5 Task detail / history

- Title, rule summary ("Daily · by 08:00 · since 1 Sep").
- Stat tiles (last 30 days): on-time %, late count, missed count.
- Month calendar dots: green on time, amber late, red missed, dashed red outline open/overdue.
  Swipe months.
- Occurrence list, newest first: Open · overdue 1d 4h / Missed · Mon still open /
  Done late · Wed 10:00 (+2d 2h) / Done 07:51. Long-press a completion → Undo.
- Viewable for any member's task (read-only if not owner, plus Nudge if overdue).

### 6.6 History tab

Group activity feed, newest first, grouped by day: completions (on time / late), misses,
nudges, new tasks. Filter by member.

### 6.7 Me

Profile (name, avatar colour, timezone), passkeys + password, notification preferences
(reminders on/off, nudges on/off, quiet hours), groups (leave, create, join), theme, sign out.

### 6.8 Principles

- Status never colour-only: always icon + text too.
- Every screen renders from IndexedDB instantly; no spinners for local data.
- Motion: short (150–250 ms), respects `prefers-reduced-motion`.

## 7. Testing

- `core`: exhaustive unit tests for rule expansion (DST, month-end, intervals), derivation
  (on-time / late / missed / undo / duplicate completion / rule change).
- Server: sync push/pull idempotency, authorization (own tasks only, membership), invite code
  rate limits.
- Client: offline e2e with Playwright (go offline, add + complete, reload, go online, verify sync).
